# تقدم تطوير منصة العامري الأدبية — 2026-11-04

## نطاق العمل
مشروع Supabase: `alameri-literary-platform` (`getzfcztlowvmznhfpjt`). واجهة الاستوديو `studio/`، والمكتبة الأصلية تبقى في `poems.json` وصفحات `poems/*.html`.

## مبدأ الاعتماد
لا تُعتمد قصيدة أو ديوان جديد تلقائيًا. تبدأ جميع القصائد والدواوين الجديدة بحالة `draft` الخاصة، ويشترط لتقديمها `submit` رتبة `poet` أو `verified_poet` أو `admin`. وظيفة `literary_action` تتحقق من هوية المستخدم المخزنة في قاعدة البيانات قبل الانتقال إلى `published`؛ يعتمد العمل النهائي صاحب حساب `admin` فقط بضغط زر الموافقة الصريح. اعتماد القصيدة وحده لا يكشف نصها للزائر ما لم يكن الديوان منشورًا أيضًا. لا تعتمد الطلبات غير المكتملة.

## المنجز
- جداول Supabase: `literary_diwans`, `diwan_poems`, `literary_drafts`, `literary_draft_versions`, `literary_review_log`.
- حماية RLS + صلاحيات أعمدة تمنع تغيير الحالة مباشرة من متصفح العضو؛ لا صلاحية للزائر للنشر أو الموافقة.
- `backend/migrations/literary_diwans_editor_workflow.sql`: ملف المصدر المعتمد للترحيل.
- `studio/#diwans`: إنشاء مسودة ديوان، إضافة مسودة قصيدة، تحميل الدواوين المنشورة، إدارة نصوص المؤلف وتقديمها للمراجعة.
- `studio/#editor`: خزنة سحابية مرتبطة بالحساب وسجل نسخ، استعادة نسخة إلى المحرر دون نشر.
- `studio/#literary-review`: صندوق طلبات الأعمال الرسمية للمدير، مع الموافقة أو الرفض المسبب.
- `studio/#community`: تصفية المشاركات بحسب أحدث المشاركات أو منشوراتي أو المتابَعين، عرض التعليقات، حذف التعليق الشخصي وروابط مشاركات منفردة.
- `posts` تُستخدم للمشاركات الاجتماعية فقط، حتى لو كان النص شعريًا؛ عدم اعتباره قصيدة رسمية.
- القصائد الأصلية المنشورة سابقًا لا تستورد إلى هذه الجداول تلقائيًا، ولا تتغير نصوصها ضمن هذا التطوير.

## اختبارات نفذت
- إنشاء الجداول الجديدة وتفعيل RLS والتحقق من قيود تحديث حقل `status` وتحقق صلاحيات وظيفة المراجعة.
- فحص الصياغة البرمجية لملفي `studio.js` و`literary-modules.js`، والتحقق من وجود عناصر واجهة لكل معرف JS وفحص تكرار المعرفات.
- التأكد من عدم وجود دواوين أو قصائد رسمية جديدة معتمدة أو منشورة في قاعدة البيانات بعد التطوير.

## متبق قبل الإطلاق العام
- اختبار وظيفي مباشر في متصفح منشور على هاتف وكمبيوتر، بحساب عضو وشاعر ومدير.
- ضبط SMTP لإرسال البريد العام، وفحص تسجيل الحساب وتأكيد البريد واستعادة كلمة المرور.
- إعداد تخزين الصور والمرفقات إذا كانت مطلوبة؛ لا حاويات Storage حتى الآن.
- قواعد البلاغات والمراقبة وإدارة المجتمع والإشعارات.
- تطوير محرر غني بالخطوط والأنماط والتحقيق اللغوي والعروضي؛ التشكيل الموجود حاليًا تجريبي.
- تجربة دورة كاملة: مسودة ديوان -> مسودة قصيدة -> تقديم قصيدة -> اعتمادها -> تقديم الديوان -> اعتماده -> معاينة الظهور العام.
- اختبار جداول ومحركات البحث والأداء والنسخ الاحتياطي، ثم توحيد عنوان الموقع الرسمي.
- التحقق من اكتمال نشر ملفات GitHub الجديدة على الاستضافة؛ الإيداع في GitHub لا يثبت ظهورها في Vercel.

## اعتبارات أمنية
- وظيفة `literary_action` هي `SECURITY DEFINER` عمدًا حتى تستطيع تعديل حالة المراجعة؛ ترفض غير المسجل وغير المدير عند `approve` أو `reject`. يجب إعادة مراجعة تنفيذها عند أي تغيير للصلاحيات.
- الإعتماد الرسمي يجب أن يبقى منفصلًا عن نشر أي مشاركة اجتماعية.
