# إعداد الاستوديو الأدبي — AL-AMERI OFFICIAL

## ما يعمل الآن دون خادم
- مكتبة القصائد التسع من ملف poems.json الأصلي، مع حفظ البدع والجواب ونسبة كل نص لصاحبه.
- استوديو كتابة بمعاينة حية، تحكم بالخط والحجم والحبر والخلفية، وطريقة عرض أشطر القصيدة.
- إدراج الحركات يدويًا، وتشكيل تجريبي لبعض الكلمات في المعاينة دون تغيير الأصل.
- حفظ المسودة تلقائيا على جهاز الكاتب الحالي فقط باستخدام localStorage، وإمكانية استعادتها وتصدير TXT.
- مشاركة القصائد والاقتباس والبحث، وتصميم RTL للهاتف/الحاسوب.
- لم نغيّر أيا من أبيات القصائد التسع أو ننقل ملكيتها.

## ما يحتاج تشغيل Supabase ليصبح حقيقيا
- إنشاء حسابات بالبريد وكلمة المرور وتأكيد البريد.
- ملف شخصي ودور عضو أو شاعر أو شاعر موثق أو مراجع أو مدير.
- نشر مشاركات الأعضاء والقصائد الرسمية حسب الصلاحية.
- التعليقات والإعجابات ومتابعة الأعضاء وحفظ المشاركات (الجداول والصلاحيات جاهزة، وبعض شاشاتها ما زال يحتاج الربط والتطوير).
- طلبات صفة شاعر ومراجعتها مع سجل قرارات، على أن يكون الاعتماد النهائي بيد المدير.

**تنبيه:** GitHub Pages استضافة ثابتة ولا يشغّل قاعدة بيانات أو خادما لتسجيل المستخدمين. يجب استخدام Supabase أو خدمة خلفية بديلة؛ لا يمكن جعل تسجيل الدخول آمنا بواجهة HTML فقط.

## تشغيل المنصة
1. اختر مشروع Supabase المعني. توجد قيمة URL عامة سابقة مهيأة في studio/config.js، لكن لا تشغّل مخطط SQL على مشروع مستخدم في نظام آخر قبل مراجعة الجداول والمشغلات الموجودة فيه. عند الشك، أنشئ مشروعا منفصلا.
2. افتح SQL Editor في Supabase، وراجع ثم نفّذ محتوى schema.sql في المشروع المخصص.
3. من Project Settings → API خذ Publishable Key العام، وليس Secret Key أو service_role أو كلمة مرور قاعدة البيانات.
4. اكتب المفتاح العام فقط في studio/config.js في المتغير anonKey. لا تضع أي مفتاح سري في GitHub.
5. في Authentication → URL Configuration اضبط Site URL وRedirect URLs على:
   - https://ahmedghazwoane8125-prog.github.io/alameri-official/studio/
6. فعّل Confirm Email في إعدادات Supabase Auth. جرّب التسجيل من متصفح خاص ببريد تجريبي، ثم تأكد من الدور member تلقائيا.
7. بعد التحقق من حساب المدير في auth.users، اعتمد دوره يدويا في SQL Editor وفق التعليق الختامي بملف schema.sql، ولا تنفذ ذلك لأي بريد غير موثق ملكيته.
8. اختبر حساب عضو: يسمح له بالمشاركة الاجتماعية فقط، ويمنع نشر القصائد الرسمية؛ ثم اختبر موافقة المدير على طلب شاعر.
9. راجع سياسات RLS قبل افتتاح التسجيل للجمهور، وشروط الاستخدام وسياسة الخصوصية وحدود إساءة الاستخدام وحماية الطلبات.
10. بعد التفعيل، أكمل وحدة الدواوين ورسائل الأعضاء والإشعارات والبلاغات قبل الإعلان عن جاهزية منصة اجتماعية شاملة.

## ملاحظات النشر والتصميم
- صفحة البداية محفوظة في index.html ومتصلة بالاستوديو الجديد.
- ملفات الاستوديو في studio/ وصفحات القصائد المستقلة في poems/.
- GitHub Pages يعيد نشر الملفات المحدثة من الفرع main، لكن نجاح الـ commit لا يكفي لضمان النشر الفوري؛ اختبر الرابط من الهاتف.
- في متصفح الهاتف عطّل خيار «عرض موقع الكمبيوتر» إن كان مفعلا، ولا تستخدم تكبير/تصغير المتصفح للحكم على التصميم قبل إعادة التحميل.
- لا تمنح منصب شاعر لمجرد تعبئة الحقول في الواجهة؛ مصدر الحقيقة profiles.role المحمي في قاعدة البيانات.
- الصفحات القديمة للشاعر لا تدخل تلقائيا في جدول منشورات المجتمع أو سجلات الأعضاء، وتظل محفوظة كما هي إلى أن يعتمد الشاعر إدارتها من لوحة خاصة.
